# Windows job cancellation diagnostic 0.8.4

The 0.8 target printed the normal sample correctly and proved document acceptance precedes backend processing. Windows UI deletion still produced no IPP cancellation request. This controls-only diagnostic preserves the verified0.8 printing executables and records the Windows-side action against one exact job ID.

Start from empty Windows and bridge queues with a fresh bridge session. Run the diagnostic before printing one supplied sample with the input tray empty. Windows and IPP job IDs are independent; the tool does not assume they match. It observes both, checks identity again immediately before a single Windows Remove-PrintJob call, and records the result and subsequent state. If the local job has disappeared, identity/selection is ambiguous, or its status is terminal outside the exact fresh Complete|Retained exception below, it makes no cancellation call. A successful local removal is not itself proof of remote cancellation; the framework log and sender report remain authoritative.

The helper does not issue direct IPP Cancel-Job, reset USB, restart/stop the spooler, remove queues, kill the bridge, submit documents, or retry deletion. Reports omit usernames and document titles. The result collector includes final JSON and incremental JSONL traces. The existing direct Cancel helper remains available separately, but must not be invoked during this diagnostic.

PowerShell5.1 mocked acceptance checks are required before packaging. They exercise exact-ID selection, terminal/disappearing jobs, ambiguous queues, process/queue/spooler changes, reused IDs, Windows API failure and outcomes with/without remote canceled state. This verifies helper decisions without touching a real printer queue. Actual Windows cancellation forwarding still requires target evidence.

The package gate checks the audited0.8 archive and extracted-file manifest, all printing binary hashes, diagnostic test result and helper hash. Source and existing dependency licenses are included. Package extraction/manifests, collector inclusion and absence of test executables/private captures are audited before handoff. Original0.8 and earlier packages are preserved.
