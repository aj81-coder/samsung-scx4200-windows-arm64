# Report a printing problem

First check power, USB, A4 paper and the tray icon's Printer status. Avoid repeated Print clicks after an uncertain result. Use the recovery steps in [USER-GUIDE.md](USER-GUIDE.md) when requested.

When a repository is published, use its issue forms for ordinary problems. There is no guaranteed response time. Please include:

- App version and whether this was a fresh install, update or an existing test queue.
- Laptop model, Windows version and ARM64 confirmation; printer model and USB connection details.
- Application and document type, A4/one-copy/single-sided settings and approximate page count.
- What you expected, exactly what happened and the full on-screen message.
- Whether paper ran out, USB disconnected, the computer slept or cancellation occurred.
- How many sheets actually printed, whether they were complete and whether any were old or duplicate output.
- The tray **Save diagnostics** ZIP after reviewing it for private names and paths, if you are comfortable sharing it publicly.

For installation failure include its `setup-result-….json` and message. For queue/recovery problems include the affected job's ID and status, without exposing a confidential document title.

Do not upload the whole data folder, recovery backups, page captures or confidential documents. A screenshot can contain private information too. A minimal harmless sample is more useful than the original private document. Successful everyday printing needs no report. For storage growth, include the approximate data-folder size and whether it contains old failed sessions or manually saved ZIPs; do not upload the whole folder or delete recovery evidence. See the housekeeping explanation in [USER-GUIDE.md](USER-GUIDE.md).

For security concerns follow SECURITY.md instead of a public issue. Other printer models, x64/Intel Windows, scanning, duplex and unsupported resolutions are feature requests rather than established compatibility.
