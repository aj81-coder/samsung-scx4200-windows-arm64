# Proposed first GitHub release

This is a prepared publication plan, not authorization to upload. No repository,
release page, public download or support account has been created.

Proposed repository name: `samsung-scx4200-windows-arm64`.
Proposed description: "Local IPP-to-USB printing bridge for the Samsung SCX-4200
on Windows 11 ARM64. Independent community project."
Proposed first tag: `v0.12.1`, marked as a pre-release/community preview.
Use [RELEASE-NOTES.md](RELEASE-NOTES.md) as the release description after resolving final checks.

Before publication, show the owner the final binary/source archives, checksums,
user guide, licence boundaries and disclosed validation limits. Obtain explicit
approval and the intended GitHub account/organization. Do not invent identity or
create a repository under an assumed account.

Publish only the prepared source tree. Exclude local evidence, captures, printer
documents, installed receipts, build outputs, compiler caches and private logs.
Use the supplied .gitattributes consistently and verify that the published
matching source archive retains its recorded checksums. Check a fresh repository
checkout with the documented build recipe as well. Review the initial commit and public text for private
data. Preserve all upstream source archives and complete component notices.

Attach these final assets together:

- SCX4200-General-Preview-0.12.1-arm64.zip, including source.zip and full notices.
- SCX4200-General-Preview-0.12.1-source.zip, the same complete matching source.
- SCX4200-General-Preview-0.12.1-SHA256SUMS.txt.

Once authorized URLs exist, link the actual repository and release download in
README/SUPPORT rather than a guessed URL. Configure a real support/security
reporting route. GitHub private vulnerability reporting must be enabled before
claiming that its private-report button exists. Never ask people to post private
documents or full recovery backups in public issues.

Keep the first release labelled as a community preview. State the physically
accepted 0.12.0 print path, device-free scope of updated housekeeping/host tests,
fresh-queue validation limits, unsigned status and supported printing features.
Feedback can improve compatibility without delaying publication for months of
routine printing. After publication, verify downloadable archive checksums and
matching source availability and record the real repository/release URLs.
