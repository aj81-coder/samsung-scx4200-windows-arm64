# Security reporting

This project handles print documents, local process controls and USB access. The listener is intended only for loopback; do not expose it through a network proxy or open firewall rule.

Do not post confidential documents, exploitable payloads, credentials or personal data in a public issue. Use the **Security → Report a vulnerability** button if available. Availability of private reporting depends on the repository settings; do not assume the button exists. If no private-report button is available, open an ordinary issue asking for a private reporting channel without technical exploit details. No email contact is established by this document.

A useful private report includes affected version, Windows version/architecture, reproducible steps with a harmless synthetic sample, expected versus actual behavior and the security impact. Review diagnostics for personal data before sharing them. Never run an untrusted test against a production printer merely to reproduce a report.

There is no established supported-version table or guaranteed security response time yet. The first release must state which build receives fixes. Older frozen previews remain historical test evidence rather than a promise of ongoing maintenance.
