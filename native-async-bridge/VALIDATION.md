# Asynchronous document bridge 0.8.0

The 0.7 target direct-cancellation test proved that a received IPP Cancel-Job stops the real ARM64 USB sender. The preceding Windows queue test contained no such request. Previously, synchronous raster processing kept Send-Document unanswered during conversion and paper waits. This version removes that dependency. Whether Windows now sends Cancel-Job requires a target test.

The generated, pinned PAPPL adaptation receives only PWG raster, counts decompressed HTTP bytes (including gzip) against32MiB, commits the complete file, sends and flushes the acceptance response, then submits the file to the framework worker. A pending job without a committed filename cannot be selected by the scheduler. A cancellation arriving before submission cannot resurrect a terminal job. Rejected input is not drained without a bound.

The worker reads a bounded file and uses guarded CUPS decoding with exact byte boundaries. It requires supported geometry, full rows for every page and clean EOF before running any renderer or USB sender. The standalone GPL renderer and the proven0.7 USB sender are retained. Whole-page hashes, bundle admission checks, journal-before-send, one processing job, child cancellation and no automatic retry remain in place. A stopped failed session retains its durable lock. Startup creates a fresh run directory and never reloads an old spool.

Failure summaries now distinguish unknown acknowledged bytes (null) from confirmed zero. Hash-bound final sender accounting is preferred; progress is a fallback and cannot establish that delivery is certain. USB acknowledged bytes do not establish physical sheets.

Local verification evidence is recorded in build/async/verification.json and its referenced test report. The package gate checks tests, PE machine architectures, Windows runtime imports, both generated framework source sets, and unchanged renderer/sender hashes. The target package contains no test sender executable, private captures or development runtime.

Target acceptance is pending: first ordinary two-page printing, then a second job with an empty tray cancelled through the Windows queue. Keep the tray empty afterwards, stop and collect; do not refill/retry until results are reviewed. Printer-buffered data may remain after cancellation. This is a foreground development bridge, not an installed service or public release.

Cancellation during receipt, conversion and sender waiting reached canceled state; no subsequent sender launch occurred after cancellation or uncertain delivery. Two normal documents and actual production mock output passed independent pixel checks. An8,772,807-byte dense page completed render/mock processing in0.734seconds locally. Truncated pages/one-byte trailing header, oversized geometry, copies, unsupported format,32MiB expansion, missing gzip trailer, bad CRC and renderer failure all stayed away from sender invocation. Native ARM64/x64 imports/machines and binary/source hashes verified. Fresh pinned guard reproduction matches compiled generated sources. No physical USB writes occurred in development.
